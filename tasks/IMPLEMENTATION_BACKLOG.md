# 实施任务 Backlog（按依赖顺序）

> 使用方法：一次只把一个 `BT-xxx` 任务交给一个 Agent。先完成依赖项并 Review，再分派下一项。除非明确说明，不允许 Agent 越级实现未来功能。

## Phase 0 — 工程基线

### BT-000 — Godot 工程初始化
- **阅读：** `AGENTS.md`、`docs/02_TDD.md`、`docs/04_ART_BIBLE.md`。
- **目标：** 检查并验证随包提供的 Godot 4.7.2 项目骨架；如有必要，修正基础场景和 Autoload stub。
- **范围：** `project.godot`、`scenes/boot/`、`scripts/autoload/`、`scripts/app/`。
- **验收：** 在 Godot 4.7.2 中打开无解析错误；运行进入 Bootstrap 场景；Autoload 可被访问；分辨率/像素设置符合 ADR。若当前 Agent 环境没有 Godot 可执行程序，必须明确标记为待本机验收，不能宣称通过。
- **不做：** 不实现模拟、业务、UI 菜单或完整存档。

### BT-001 — 核心类型与 ID 规范
- **依赖：** BT-000。
- **阅读：** TDD 第 3、12 节，Mod Spec 第 3–6 节。
- **目标：** 定义 `ContentId`/ID 校验、`Result` 返回结构、领域事件基础类型、核心 enum。
- **范围：** `scripts/shared/`、`scripts/domain/`。
- **验收：** 有测试覆盖合法/非法 ID、错误结果和事件构造；领域类型不依赖 Node。

## Phase 1 — 银行大厅表现

### BT-002 — 主世界场景与像素相机
- **依赖：** BT-000。
- **阅读：** Art Bible 第 3–6 节，TDD 第 5、10 节。
- **目标：** 建立 World、TileMapLayer、Y-sort 层和 Camera2D。
- **范围：** `scenes/world/`、`assets/environment/`、`scripts/presentation/`。
- **验收：** 显示可编辑地面、墙体和占位家具；Camera 可移动；Nearest 过滤、整数缩放可观察；无 UI 文字烘焙进背景。
- **不做：** 不做完整寻路与经营逻辑。

### BT-003 — 交互设施和逻辑导航网格
- **依赖：** BT-002。
- **目标：** 建立 ServiceStation 场景和逻辑格点坐标到等距屏幕坐标转换。
- **验收：** 点击柜台可选中；导航系统知道哪些格可走；无法到达时返回明确错误。

### BT-004 — 角色占位与基础动画
- **依赖：** BT-002。
- **目标：** 建立 EmployeeActor、CustomerActor 的表现层，先用占位 SpriteSheet。
- **验收：** Idle/Walk/Work/Talk 状态能够切换；角色脚底锚点稳定；Y-sort 正确。
- **不做：** 不做员工领域属性和招聘。

## Phase 2 — 实时模拟

### BT-005 — GameClock 固定步长
- **依赖：** BT-001。
- **阅读：** TDD 第 7、8 节。
- **目标：** 实现暂停、1x、2x、3x 和模拟分钟 Tick。
- **验收：** 速度不改变每个模拟 Tick 的逻辑；暂停后 Tick 停止；同样 Tick 数在任意 FPS 下得出相同结果；有追帧上限测试。

### BT-006 — Customer/Employee 领域状态机
- **依赖：** BT-001、BT-005。
- **目标：** 实现客户、员工纯领域状态机，不涉及 Sprite 动画。
- **验收：** 合法/非法状态转换有测试；员工不可同时承担互斥任务。

### BT-007 — ServiceRequest 队列
- **依赖：** BT-006。
- **目标：** 实现请求队列、优先级和超时。
- **验收：** 请求排序确定；同优先级按创建时间；超时客户离开；请求状态可查询。

### BT-008 — Employee Dispatcher
- **依赖：** BT-007。
- **目标：** 根据技能、状态、岗位权限、优先级与距离分配服务请求。
- **验收：** 可配置权重；分配结果可解释；没有合适员工时请求留队而非丢失。

### BT-009 — 客户完整大厅链路
- **依赖：** BT-003、BT-004、BT-008。
- **目标：** 客户生成→寻路→排队→服务→完成/离开。
- **验收：** 运行 1 天无状态卡死；队列/员工状态与世界表现同步；确定性测试通过。

## Phase 3 — 金融闭环

### BT-010 — Ledger 双分录账本
- **依赖：** BT-001。
- **阅读：** `docs/03_ECONOMY_SPEC.md`。
- **目标：** 账户、Journal Entry、借贷平衡校验和交易历史。
- **验收：** 存款、取款、放贷测试借贷平衡；禁止直接设置账户余额；金额整数。

### BT-011 — FinanceEngine
- **依赖：** BT-010。
- **目标：** 实现利息计提、手续费、工资、设施成本和利润汇总。
- **验收：** 速度倍率不改变每日结果；利率用基点；有整数舍入测试。

### BT-012 — DailySettlement 与报告 DTO
- **依赖：** BT-011。
- **目标：** 实现日终固定顺序和 DailySettlementRecord。
- **验收：** 运行 30 天账务无不平衡；重复调用同一天结算不会重复记账；每项利润可追溯。

## Phase 4 — 员工和组织成长

### BT-013 — 招聘与候选人系统
- **依赖：** BT-006、BT-011。
- **目标：** 候选人定义、面试结果、录用、薪资和离职。
- **验收：** 员工唯一 ID；薪资入账；HR 解锁逻辑不依赖 UI。

### BT-014 — DepartmentDefinition/Instance 和部门管理
- **依赖：** BT-001、BT-011。
- **目标：** 创建、升级、成本、岗位和能力解锁。
- **验收：** 运营/HR/信贷/风控四部门至少各有一个可测试的机制效果；部门成本结算正确。

### BT-015 — ModifierService 与部门协同
- **依赖：** BT-014。
- **目标：** 统一处理 add/multiply/应用范围与上限。
- **验收：** 同一个目标的多个效果按固定顺序计算；无重复叠加/无限堆叠；测试覆盖。

### BT-016 — Policy 系统
- **依赖：** BT-015。
- **目标：** 政策前置条件、互斥组、成本和效果。
- **验收：** 稳健/激进路线均至少 3 节点；两者有不同经营结果；不满足条件无法采用。

## Phase 5 — 事件与 UI

### BT-017 — EventDefinition/事件调度器
- **依赖：** BT-001、BT-015。
- **目标：** 事件触发条件、权重、冷却期、选项、后续事件。
- **验收：** Seed 可重现；事件有冷却；事件链按条件推进。

### BT-018 — 主 HUD 与 Inspector
- **依赖：** BT-002、BT-005、BT-009。
- **目标：** 顶栏、侧导航、右侧实时检视器、底部速度/事件条。
- **验收：** 数值来自状态查询；UI 通过 Command 发起操作；中英日文本不溢出。

### BT-019 — 招聘/部门/政策/事件弹窗
- **依赖：** BT-013、BT-014、BT-016、BT-017。
- **目标：** 构建各管理页面和关键弹窗。
- **验收：** 有完整的禁用原因、确认提示和结果反馈。

### BT-020 — 日终报告 UI
- **依赖：** BT-012、BT-018。
- **目标：** 利润、现金/存款/贷款、满意度、员工疲劳和风险变化。
- **验收：** 每个数值都对应真实 DTO；展示主要变化原因。

## Phase 6 — 工程化

### BT-021 — Save DTO / SaveService
- **依赖：** BT-012、BT-014、BT-016、BT-017。
- **目标：** JSON 保存、加载、备份、save_version 和迁移入口。
- **验收：** 读写往返一致；损坏文件不覆盖正式档；迁移 Fixture 测试通过。

### BT-022 — 原版多语言
- **依赖：** BT-018、BT-019。
- **目标：** PO/MO 翻译、语言切换、缺失 Key 日志。
- **验收：** 简中、英语、日语 MVP 页面覆盖；切换后 UI 刷新。

### BT-023 — Mod Manifest / ContentRegistry Loader
- **依赖：** BT-001、BT-014、BT-016、BT-017、BT-022。
- **阅读：** `docs/06_MODDING_SPEC.md`。
- **目标：** 文件夹/ZIP 扫描、Manifest 校验、依赖排序、内容注册和报告。
- **验收：** 合法样例 Mod 可新增部门/政策/事件；坏 Mod 被拒绝并指出原因；不执行脚本。

### BT-024 — Mod 安全和兼容测试
- **依赖：** BT-023、BT-021。
- **目标：** 重复 ID、路径穿越、尺寸限制、缺依赖、存档缺 Mod 和版本检查。
- **验收：** 所有测试通过；缺失内容不静默丢弃。

### BT-025 — 30 天 End-to-End 场景
- **依赖：** BT-009、BT-012、BT-016、BT-017、BT-021。
- **目标：** 自动模拟/可玩 30 天挑战。
- **验收：** 无重复结算、无无法解释的货币生成、无崩溃；每日报告可读。
