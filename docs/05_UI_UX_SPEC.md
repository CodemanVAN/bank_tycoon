# 05 — UI/UX 设计规范

## 1. UI 原则

1. **大厅优先：** 大部分时间玩家看见正在运转的银行大厅，而不是被菜单遮满。
2. **先说明问题，再提供操作：** 队列过长、流动性危险、员工疲劳等状态必须有原因、影响和可执行建议。
3. **关键决策少而重要：** 普通业务自动处理；玩家主要处理优先级、异常事件、组织和战略。
4. **信息分层：** 顶栏看核心指标；左右面板看运营；底部/弹窗处理管理系统。
5. **像素清晰：** 所有文字/图表由 Godot 原生 UI 绘制；不可把 AI 图中文字作为真实 UI。

## 2. 主游戏屏幕

推荐 16:9 主布局：

- 顶栏（高度约 32–40 px 逻辑单位）：天数、游戏时间、现金/流动性、存款、员工数、速度/暂停、设置。
- 左侧导航（宽约 48–64 px）：总览、财务、员工、部门、政策、事件、建筑/设施、设置。
- 中央世界视口：银行大厅；支持镜头拖动/缩放（缩放范围需保持像素整数倍率或最近邻）。
- 右侧检视器（宽约 120–150 px）：当前选中员工/客户/设施、队列和实时警告；无选中对象时显示运营概览。
- 底部时间/事件条：暂停、1x、2x、3x、通知和当天利润估算。
- 日终报告：覆盖层/独立面板，不与实时大厅 UI 同时争夺注意力。

逻辑分辨率 640x360 时允许依据屏幕比例将侧栏折叠为图标；不强制每个面板同时常驻。

## 3. 一级页面

### 总览

显示当日利润估算、客户满意度、队列压力、流动性状态、事件提醒。避免展示过多不可操作指标。

### 财务

显示资产负债表简化版、收入成本拆分、贷款组合、存款趋势、流动性和不良贷款。趋势图支持切换日/周范围。

### 员工

员工列表、岗位、技能、特质、疲劳、薪资、忠诚度、培训与晋升。列表支持按岗位、效率、疲劳排序。

### 部门

部门卡片包含等级、员工数、成本、效果、升级条件、部门主管和关联能力。成立新部门前展示成本及日常负担。

### 政策

显示政策路线、前置条件、互斥分支、成本、效果和不利影响。未满足节点显示具体缺少条件。

### 事件

事件详情、当前风险来源、选择项、每个选择的即时/延迟后果。无法选择的选项应显示锁定原因。

### 建筑/设施

柜台、办公桌、服务台、ATM 和装饰等。第一版只允许有限放置/升级，不做复杂自由建造。

## 4. 关键弹窗

- 招聘/面试：候选人资料、岗位匹配、薪资要求、面试问题简选。
- 贷款审批：借款金额、利率、期限、信用分、风险等级、批准/拒绝。
- 事件选择：事件描述、原因、选项、预估影响和风险。
- 日终报告：利润拆解、资产负债变化、客户/员工/风险表现、明日预警。
- 创建/升级部门：初始成本、日成本、功能解锁、人员需求。

## 5. 信息层级

- L0 必须立即注意：营业暂停、严重流动性风险、重大事件倒计时。
- L1 日常经营关注：队列过长、员工超负荷、贷款积压。
- L2 经营趋势：利润、声誉、满意度、部门效率。
- L3 详细信息：员工隐藏特质提示、事件历史、财务细项。

颜色仅为辅助；每个状态必须配合图标、文本或形状差异。

## 6. 交互规则

- 所有重要操作都有可见反馈和错误原因。
- 不允许仅靠 Hover 提供唯一信息；点击/焦点也能获得提示。
- 长按/拖拽不是唯一操作方式；提供点击选择和下拉菜单的替代路径。
- 破坏性操作（解雇、永久政策选择、重大贷款）二次确认或显示明确风险。
- 关键玩家动作在暂停状态下允许操作。
- 游戏时间暂停时，UI 动画可以继续做轻量动效，但不得推动业务模拟。

## 7. 可读性和本地化

- UI 容器必须允许文本自动换行和高度扩展。
- 中文/日文通常需要较短的行宽；英文可能产生更长单词。
- 不要把按钮宽度写死为适配中文的值；使用最小宽度和最大宽度范围。
- 数字使用本地化格式化；货币单位与游戏币种在设置/存档定义。
- 字体必须覆盖简中、英文、日文常用字符；缺字时使用经过测试的回退字体。
- 高对比模式和 UI 缩放作为后续设置项，但 UI 不得依赖极细像素线条。

## 8. 响应式规则

- 基准宽屏：16:9。
- 超宽屏：世界视口扩展；UI 固定锚定，中央可见更多场景。
- 窄窗口：允许折叠左导航/右检视器；保证速度控件与事件状态可访问。
- 最小窗口尺寸不得小于能够完整显示核心控制条的尺寸。
- 任何面板不应遮住当前选中对象的全部世界可见区域；选中对象可通过镜头聚焦或边缘标记定位。
