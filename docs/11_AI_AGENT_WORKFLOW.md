# 11 — AI Agent 分段开发工作流

## 1. 基本策略

不要把“开发整款银行模拟游戏”交给 Agent 作为一个任务。采用小批量、可编译、可运行、可测试的 vertical slice 任务。每次只让 Agent 实现一个明确输出，并由人类检查差异和验收结果。

## 2. 每个任务的输入

Agent 必须获得：

1. 本文件（AGENTS.md）。
2. 对应 GDD/TDD 专题文档。
3. 一个任务 ID 和清晰的完成标准。
4. 当前项目树/已有接口。
5. 不允许改变的架构边界。

## 3. 推荐提示词模板

```text
你是 Bank Tycoon 项目的 Godot 4.7.2 GDScript 开发 Agent。
先完整阅读根目录 AGENTS.md 和以下设计资料：{指定文档}。
本任务：{任务 ID + 标题}。
目标：{一句话目标}。
允许修改：{明确目录/文件}。
禁止修改：{不相关目录或已冻结接口}。
验收标准：
- {标准 1}
- {标准 2}
- {标准 3}

执行要求：
1. 先检查当前代码和资源，不要覆盖未提交改动。
2. 先说明实现方案和涉及的类/接口，再开始修改。
3. 不引入未批准插件，不执行任意 Mod 脚本。
4. 业务规则放在 Domain/Application，不放进 UI 或 Sprite 节点。
5. 添加或更新测试；实际运行你能运行的测试。
6. 不顺手重构其他模块。
7. 最终汇报修改文件、测试命令与结果、未完成项和后续依赖。
```

## 4. 每个任务的交付物

- 修改后的项目文件。
- 测试或验证脚本。
- 若更改内容格式，则更新 JSON Schema / 示例。
- 简短实施报告。
- 明确列出“未实现/未测试”的事项。

## 5. 人工 Review 清单

- 是否违反 AGENTS.md？
- 是否把领域逻辑写在 Node/UI 中？
- 是否把静态 Definition 和 Runtime State 混在一起？
- 是否直接改余额而不是写 Ledger？
- 是否有硬编码玩家可见文本？
- 是否引入非命名空间内容 ID？
- 是否有帧率依赖的模拟？
- 是否增加了无任务要求的新功能？
- 是否有实际测试结果？

## 6. 适合并行的工作

在接口稳定后，可并行：
- 像素资产清理/场景 TileSet 生产。
- UI 主题和布局。
- 部门/政策/事件 JSON 内容编写。
- 翻译 PO 初稿。
- QA 测试用例。

不建议并行：
- 多个 Agent 同时修改 GameClock/Simulation tick。
- 多个 Agent 同时修改 BankState/Ledger。
- 多个 Agent 同时设计 Mod Schema。
- 多个 Agent 同时重构目录或全局 Autoload。

## 7. 任务完成后的 Git 规则

- 每个任务一个分支或一个独立提交。
- 提交标题示例：`feat(simulation): add fixed-step game clock`。
- 不把自动生成的大量未审查素材一次性混入核心逻辑提交。
- 大型资产另做单独提交，附 Asset Catalog 更新。
